## 🎯 What is Bidya PM?

Most AI tools act as simple text expanders—churning out bloated 15-page PRDs, speculative user stories, and feature requests that flood engineering sprint backlogs without answering: *does this solve a validated problem?*

**Bidya PM** is an agentic product management intelligence system designed for **Antigravity, Claude Desktop, Claude Code, Cursor, OpenAI Codex/Custom GPTs, and Gemini Gems**. It operates not as a passive scribe, but as a rigorous, senior product advisor that:
1. **Separates symptoms from true functional needs** before a single ticket is created.
2. **Deconstructs initiatives into thin vertical slices** to validate risk in days, not quarters.
3. **Applies AI-native evaluation hygiene** (golden sets, evals, failure fallbacks) to non-deterministic features.
4. **Enforces outcome telemetry** (metrics and counter-metrics) to prevent vanity gaming.

### 1. Demand & Stakeholder Request Decoding (`/decode-demand`)
* **Problem Solved:** Sales, executive, or client requests often arrive as pre-packaged technical solutions (e.g., *"We need an AI chatbot in settings immediately"*).
* **Functional Output:**
  - **Stated vs. Real Pain:** Maps the literal request to functional, social, and emotional Jobs-to-be-Done (JTBD).
  - **Strategic Drift Assessment:** Scores whether the request aligns with active quarterly bets or introduces distraction.
  - **Lean Counter-Proposals:** Generates low-lift alternatives addressing the root cause.
  - **Executive Diplomacy Script:** Delivers diplomatic, objective communication scripts to manage stakeholder expectations.

### 2. Continuous Discovery & Opportunity Mapping (`/opportunity-map`)
* **Problem Solved:** Feature roadmaps decouple development work from top-line business goals.
* **Functional Output:**
  - Builds structured **Opportunity Solution Trees (OST)** connecting North Star metrics to granular user friction points.
  - Generates bifurcated bets: **Low-Risk Incremental Lift** vs. **High-Impact Exploratory Bets**.
  - Formulates rapid 48-hour hypothesis micro-probes and fail-fast signals.

### 3. Thin-Tracer Vertical Slicing (`/slice-deliverable`)
* **Problem Solved:** Monolithic epics and multi-sprint releases deliver zero user value until 100% finished.
* **Functional Output:**
  - Slices large capabilities into thin, vertically deployable increments across UI, business logic, and telemetry.
  - Formulates strict **Gherkin Acceptance Criteria** (`Given / When / Then`).
  - Attaches **Telemetry Hooks & Event Schemas** with explicit success and failure thresholds.

### 4. AI-Native Product Evaluation (`/ai-product-eval`)
* **Problem Solved:** Teams treat LLM/ML features like deterministic software, shipping brittle experiences with poor user trust.
* **Functional Output:**
  - **Heuristic Justification:** Evaluates whether non-deterministic models are truly necessary over simple heuristics.
  - **Golden Evaluation Benchmarks:** Defines evaluation datasets, precision/recall expectations, and latency limits.
  - **Graceful Fallbacks:** Designs deterministic degradation pathways for hallucination or timeout states.
  - **Continuous Data Flywheels:** Establishes explicit and implicit user telemetry loops to refine model performance.

## 🧠 The Bidya Product Axioms

1. **Outcomes Over Output:** Velocity without telemetry is just high-speed waste. Never define success by shipped epics; define it by measurable behavioral shifts.
2. **Deconstruct Before Delivering:** Treat every stakeholder request as a symptom, not a specification.
3. **Tracer Bullets Over Mega-PRDs:** High-performing teams build the thinnest testable slice that resolves uncertainty.
4. **AI-Era Pragmatism:** Prioritize evals, fallback states, latency budgets, and feedback loops over static Figma screens.
5. **Constructive Friction:** Respectfully challenge assumptions, surface blind spots, and demand validation.
